# CAN2 接 M3508 + C620：首次转动

## 这版程序做什么

| 总线 | 设备 | 程序行为 |
| --- | --- | --- |
| CAN1 | 达妙 J4310-2EC | 保留原来的 ID 扫描和速度模式；DBUS S1 使能，CH0 控制速度 |
| CAN2 | 一台 C620 + M3508 | 监听反馈自动识别电调 ID；DBUS S1+S2 使能，速度 PI 闭环 |
| CAN3 | 预留 | 不初始化、不启动、不发送控制帧，也不调用达妙解码 |

**默认程序不会自动启动电机。** 达妙只有 DBUS 在线且 S1 位于 `DBUS_ARM_S1_VALUE` 时使能；C620/M3508 还要求 S2 位于 `DBUS_FRICTION_S2_VALUE`。第一次使用请固定电机、让输出轴空载；如果带轮子，把轮子架空。需要立即停机时切断对应动力电源。

达妙扫描失败时只跳过 CAN1 的使能，CAN2 仍可测试。启动扫描只进行一次，达妙稍后才接入时需要复位主控。

## 遥控器 DBUS 接入

本工程采用用户提供的 DT7/DR16 标准 DBUS：100 kbit/s、8 位数据、偶校验、1 个停止位，每约 14 ms 一帧 18 字节。H723 的 UART7 RX 使用 PE7，程序打开了 USART 硬件 RX 反相；USART10 的 PE3 继续输出 115200 日志。DR16 的 DBUS 信号、电源和主控共地，接收机供电按接收机手册执行，不能把 5 V 信号直接接到未经确认的 MCU 输入。

默认控制关系如下：

- `S1=1`：达妙速度模式允许；`S1` 其他位置或 DBUS 超时，达妙发送失能帧并给零速度。
- `S2=1` 且 S1 已使能：C620/M3508 运行到 `DJI_DEFAULT_OUTPUT_RPM`，默认 30 rpm 输出轴速度。
- `CH0`：达妙速度命令，摇杆中心为 0，满行程约 ±2 rad/s。
- `CH1..CH3`：当前只打印，后续可接云台另一轴、摩擦轮转速或发射机构。

DJI 手册将开关值定义为：1=上、2=下、3=中。若你的遥控器安装方向相反，只改 `User/dbus.h` 中的两个开关宏，不要改 DBUS 位解析。

## 为什么大疆不用逐个 ID 扫描

C620 上电后默认以 1 kHz 主动发送反馈，帧 ID 是 `0x200 + 电调编号`：

| 电调编号 | 反馈 ID | 电流控制组 | 该电机占用字节 |
| --- | --- | --- | --- |
| 1～4 | 0x201～0x204 | 0x200 | 依次为 0～1、2～3、4～5、6～7 |
| 5～8 | 0x205～0x208 | 0x1FF | 依次为 0～1、2～3、4～5、6～7 |

程序监听有效反馈至少 1 秒，要求目标电调累计至少 10 帧且最近 100 ms 内有反馈。自动模式只允许发现一个编号；发现多个编号会停在 `MULTI-ID`，不会任意选一个转动。识别过程中输出为零电流；完全没有反馈时只接收、不发送。

这只是识别现有 ID，不修改电调 ID，也不能检测两个电调用了同一个 ID。首次测试 CAN2 **只接一个 C620**。该总线专用于 C620/M3508，不能仅凭 `0x201～0x208` 区分其他使用相同 ID 的设备。

正常运行后推荐把识别出的编号写入 `User/dji_motor.h` 的 `DJI_MOTOR_ID`，减少以后误选设备的可能。`0` 为自动，`1～8` 为固定编号。固定模式允许观察到其他编号，但本程序仍对其他电机发送零电流；这是单电机测试程序，不是多电机控制器。

## 接线

先断电连接。CAN1 达妙接线保留。

1. **M3508 ↔ C620**：三相动力线按相同颜色连接，同时插好 7-Pin 数据线；两者缺一不可。
2. **C620 ↔ CAN2**：C620 CAN 红线接开发板 CAN2 的 `H`，黑线接 `L`。这里黑线是 CAN_L，不是电源负极。优先使用板上的 CAN2 两针信号接口，按板上 H/L 标识接，不按插头朝向猜测。
3. **C620 供电**：XT30 电源接口按正负极接 24V 电源支路。主控和 C620 共地。可由同一个足够容量的 24V 电源分别给主控和 C620 供电。
4. **终端电阻**：只有主控和一个 C620 时，在总线两个物理末端各接入 120Ω；核对主控 CAN2 的终端跳线和 C620 的终端开关，避免重复接入。断电后 H/L 间通常约为 60Ω。
5. C620 的 **PWM 口保持断开**，本程序使用 CAN 控制。

开发板 CAN2 的 MCU 引脚为 `PB5=RX`、`PB6=TX`。C620 接的是经过收发器的 CAN_H/CAN_L 接口，不能直接接 PB5/PB6。

开发板两路可控电源口各持续 5A；M3508 手册给出的额定工况电调输入电流为 10A。**C620 使用独立 24V 供电支路，不从开发板可控电源口承担满功率负载。** 若使用 XT30(2+2) 接口引出 CAN，避免把另一路电源与板上输出直接并接。

## 编译、下载、观察

### Keil

打开 `MDK-ARM/CtrBoard-H7_FDCAN.uvprojx`，`User/dji_motor.c` 和 `User/dbus.c` 已加入 `bsp` 分组，同时补齐 UART 源文件。正常 Build 后按原有下载方法烧录。不要下载旧的构建文件。串口文字已改为英文标识，避免 ARMCC5 对 UTF-8 中文字符串的编码解析错误。

### CMake

在已配置 ARM GCC、CMake、Ninja 的终端中执行：

```powershell
cmake --preset Debug
cmake --build --preset Debug
```

本次验证用单独的 `build/can2-check` 构建目录，生成的 `CtrBoard-H7_FDCAN.hex` 可用 STM32CubeProgrammer/ST-Link 下载；HEX 自带地址。若使用 BIN，起始地址为 `0x08000000`。本次仅生成固件，没有执行烧录。

### 串口

沿用 USART10 日志：`PE3/TX → USB-TTL RX`，共地，`115200 / 8N1`，使用 3.3V TTL。开发板串口与电机自己的调参串口不是同一个接口。

启动后先执行达妙原有初始化，再进入两路控制。几秒内应看到类似日志：

```text
[DJI] WAIT id=0 seen=00 out=0rpm cmd=0 T=0 rx=0
[DJI] STOP id=1 seen=01 out=0rpm cmd=0 T=25 rx=...
[RC] ONLINE arm=1 friction=1 S1=1 S2=1 CH1=1024 CH2=1024 CH3=1024 CH4=1024 frames=...
```

以上是日志格式示例，不是实测值。`out` 是换算后的输出轴转速，显示为整数；`cmd` 是发送给 C620 的电流指令原始值；`rx` 是选中电调累计有效反馈帧数；`seen` 是已出现编号的位图，ID1 对应 `01`，ID2 对应 `02`，ID1+ID2 对应 `03`。

先确认 `[RC] ONLINE arm=0 friction=0` 能稳定出现，再把 S1/S2 按上面的顺序拨到使能位置。达妙先做低速点动；C620 先空载、低速确认方向。

C620 不使用达妙的 `FF...FC` 使能帧，不需要按 SET 才能转动；供电、反馈、编号正常后即可接收电流命令。绿灯每秒闪几次就是它的 ID。

## 改速度、方向和停止

配置集中在 `User/dji_motor.h`：

```c
#define DJI_MOTOR_ID             0U     // 自动识别；识别后可改成实际编号
#define DJI_DEFAULT_OUTPUT_RPM   30.0f  // 输出轴 rpm，负数反转，0 为零电流
#define DJI_CURRENT_LIMIT        2000   // 约 ±2.44A 转矩电流
#define DJI_SPEED_KP             4.0f
#define DJI_SPEED_KI             8.0f
```

改配置后重新编译、烧录。M3508 的精确减速比使用 `3591/187`；30 rpm 输出轴约对应 576 rpm 转子。PI 使用转子 rpm 计算误差，控制值使用高字节在前的有符号 16 位整数，`±16384` 对应 `±20A`。这里的转矩电流不能直接当作电源输入电流。

代码中的可调变量：

- `dji_target_output_rpm`：运行目标，允许 -120～+120 rpm。超过范围或写入 NaN 会停机锁定。
- `dji_run_enable`：设为 0 后，在程序继续运行时下一个控制周期发送零电流；设为 1 且没有故障时恢复缓加速。
- 运行中 `dji_run_enable` 由 DBUS 自动管理；失联或开关回安全位后，下一个控制周期发送零电流。

零目标或禁止运行意味着零电流、自由滑行，不是主动刹车或保持位置。暂停调试器不等于执行停止命令；电机仍在运动时优先断开动力电源。

默认 100Hz 速度 PI、30 rpm/s 缓加速、约 2.44A 电流限制。PI 参数是空载台架起点，尚未做实机调参，不保证带负载性能；不要为了让堵住的电机转动而直接提高限流。

## 日志排查

| 日志 | 含义与处理 |
| --- | --- |
| WAIT，seen=00 | 没收到有效 C620 反馈；检查供电、7-Pin/三相线、CAN2 H/L、共地、终端电阻、C620 状态灯；确认反馈频率没有被调参软件关闭或大幅降低 |
| WAIT，seen 非零 | 正在等待识别窗口或指定 ID；固定 ID 模式核对实际编号 |
| MULTI-ID | 自动模式发现多个编号；只接一个 C620 后复位，或确认目标后设置固定 ID |
| RX-TIMEOUT | 选中电调超过 100ms 无反馈；检查线路、供电，恢复后复位主控 |
| HOT | 温度达到本程序设定的 70℃ 台架阈值；断电检查并冷却后再试 |
| LOOP-LATE | 运行中的主循环超过 50ms 未执行控制；检查是否打断点或增加了阻塞操作 |
| TX-FAIL | CAN2 入队失败；程序取消待发队列并尝试发送零电流；检查总线后复位 |
| STALL | 目标至少 10 rpm、转子低于 50 rpm 且接近限流持续 2 秒；检查是否堵转、线材异常或负载过大 |
| OVERSPEED | 输出轴速度绝对值超过目标绝对值 60 rpm；检查反馈、型号和控制效果 |
| BAD-TARGET | 目标超出 ±120 rpm 或不是有限数值 |

故障均锁定到主控复位；恢复反馈不会自动恢复转动。运行禁止后重新使能也不能清除故障。CAN 线路完全断开时零电流帧无法送达，软件不能替代动力断电。

CAN2 中断只接收缓存，不打印每帧日志；三路电机协议已隔离。CAN1 参数读写和控制格式沿用原实现，周期性逐帧 TX 日志关闭，主循环按经过的时间调度。当前主循环仍有阻塞式串口状态日志，因此 100Hz 是调度目标，会存在日志引起的周期抖动。
